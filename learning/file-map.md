# File map

Every file in this project and why it exists.

- `.gitignore` — known. Yours, from lesson 11: what Git never tracks anywhere in the project: every `node_modules` and `__pycache__`, `backend/.venv`, your `learning/scratch/git-practice` repo, and your root clipboard files `/ex.html` and `/ex.jsx`. Lesson 11 also untracked the copies already committed (`git rm -r --cached`), since `.gitignore` only stops new files.
- `.altitude` — known. Links this folder to your Altitude journey. Written by Altitude; you never edit it.
- `DESIGN.md` — known. The design from your Altitude prototype ("Tripwire"): colours, fonts, spacing, and the parts each screen holds. Every screen in the app is built to it. Written by Claude in lesson 6.
- `backend/` — known. Home of all the Python code (price checker, FastAPI, database). You chose this so Python and the future `frontend/` React code keep separate dependencies and tooling.
  - `backend/pyproject.toml` — known. The project's source of truth: its name, Python version, and the packages it depends on (`httpx` for web requests). Changed with `uv add`, not by hand.
  - `backend/uv.lock` — known. The lock file: exact versions of every installed package, so another install gets identical ones. Generated by uv; never edit.
  - `backend/price_check.py` — known. Your price checker: `fetch_prices` asks CoinGecko for the coins' USD prices, `display_prices` prints them, and the `__main__` block turns a failed fetch into a clear message. You wrote it in lesson 4; later the FastAPI service and the scheduler will import `fetch_prices`. Lesson 5 added a hard-coded `target` and `target_hit` (the crossing rule: `above` hits at or over the price, `below` at or under) plus `report_target`, which prints HIT or waiting; Claude wrote these and you reviewed them.
  - `backend/schema.sql` — known. Yours, from lesson 12: the design of Tripwire's database. Creates the `readings` table (one row per coin per price check): an identity `id` primary key, required `coin_id` text, `price` as exact `numeric` that must be above 0 (you switched from `double precision` so the "exactly on the target" rule compares exactly), and `created_at` as a `timestamptz` that is required and defaults to `now()`. Rebuild with `psql -d crypto_tracker -f backend/schema.sql` (on an empty database; it errors if the table already exists). The database itself, `crypto_tracker`, lives in your local PostgreSQL 14, not in this folder; it holds two hand-inserted readings (bitcoin, ethereum).
  - `backend/__pycache__/` — known. Machine-made: Python's compiled copy of `price_check.py`. Ignored by Git; safe to delete.
  - `backend/.venv/` — known. The backend's private Python environment, where `httpx` actually lives. Machine-made; `uv run` uses it, and `uv sync` rebuilds it from the two files above.
- `frontend/` — known. The React app, made with Vite in lesson 6 (`npm create vite@latest frontend -- --template react`). Its own dependencies and tools, separate from `backend/`. Run it with `npm run dev` from here.
  - `frontend/index.html` — known. The one page the browser downloads; React draws everything into its `root` div. Lesson 7: Claude added the Google Fonts `<link>` (Hanken Grotesk, JetBrains Mono) and the "Tripwire" tab title.
  - `frontend/src/main.jsx` — known. Loaded by `index.html`; tells React to draw `App` into `root`. Rarely edited.
  - `frontend/src/App.jsx` — known. The top of the app. Since lesson 9 it keeps the current path in state (`useState(window.location.pathname)`) and `screenFor(path)` picks one screen per path (`/`, `/new-target`, `/readings`, `/job-runs`, `/json`, else "Page not found."). You wrote `handleAddressChange` (`setPath(window.location.pathname)`), which a `popstate` listener calls; the `useEffect` that adds and removes that listener was scaffolded and comes due in the "Load targets into the Targets page" lesson. Lesson 10: `App` now returns your shared `TopBar` above whichever screen `screenFor` picks (you wrote that return). Claude added `navPathFor(path)`, which keeps Targets marked on `/new-target`. Lesson 11: at your request, Claude replaced "Page not found." with `RedirectHome`, which swaps an unknown address for `/` with `history.replaceState` (so Back still works), and added a catch-up `handleAddressChange()` call in `App`'s effect, because a child's effect runs before `App` starts listening. You read the diff, tested it, and committed it.
  - `frontend/src/router.js` — known. Your `navigate(to)`: `pushState` moves the address without a reload, then it dispatches a `popstate` event so `App` hears about it and redraws. Every in-app link goes through it. Lesson 10: Claude added `followLink(event)`, the click handler for nav links: `preventDefault()` stops the full page load, then it calls `navigate` with the link's own `href`.
